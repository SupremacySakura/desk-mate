# DeskMate 双端界面：有线扩展显示

## 目标

用户打开 macOS 和鸿蒙应用并接上 USB 数据线后，能在界面上看懂当前进度、完成必要授权，并在平板上看到 Mac 的扩展桌面。参考 Oink 的设备状态、显示区域与分组设置的层次，不引入 Oink 的多设备或无线配对流程，也不复用其标识或源码。

## macOS

| 页面 | 内容与操作 |
| --- | --- |
| 扩展显示 | 显示当前连接阶段、扩展显示器来源、画面发送状态和反向输入状态。发生问题时显示下一步；把原始计数和日志留给诊断。 |
| 设置 | 选择当前可用的扩展显示器，提供录屏和辅助功能的状态与系统设置入口，允许启停反向输入。缺少辅助功能权限时，仍可发送画面。 |
| 菜单栏 | 保留打开主窗口及查看简要状态的快捷入口。不能把正在采集或编码标成平板已出画。 |

不假定不同 Mac 上的显示器 ID 相同。可以借用已有的扩展显示器；未找到可用来源时应给出明确提示，不静默改为采集主屏。

## 鸿蒙

| 页面 | 内容与操作 |
| --- | --- |
| 首页 | 说明如何打开 Mac 应用并插线，展示等待设备、等待授权、建立会话、准备画面、画面可用或发生错误。没有可用会话时不显示可点击的「返回画面」。 |
| 全屏 | 一个新会话首次真正出画时自动进入；默认让画面独占屏幕，提供可发现的返回入口。返回首页不是断开，也不因同一会话再次收到帧而自动回到全屏。 |
| 设置 | 提供可实际生效的帧率显示开关及连接诊断。帧率指平板侧的真实渲染帧率，不用协商的目标帧率代替。 |

用户返回首页或进入设置时，能保留的会话应继续保留。若平台限制导致画面表面无法继续使用，界面需说明状态并允许用户主动返回画面。设计和实现要验证页面切换不会意外销毁解码所需的表面。

## 真机验收

- 在当前验证环境中，前置条件只包含安装好两端应用、USB 数据线和可用的扩展显示器。用户从系统界面启动应用、授权并看到画面，不运行开发命令。若仍需 `make device-foreground`，该项未通过。
- USB 配件打开、会话建立和首帧上屏可以区分。平板没有真实出画时，不自动进入全屏；Mac 没有可靠的对端上屏证据时，只报告「正在发送」。
- 首帧后从全屏回首页、打开设置、返回画面；会话在有效时不因页面切换意外断开，也不会把用户自动拉回全屏。
- 拔线回首页并提示重新插线；授权拒绝、缺少扩展显示器和启动失败各有可执行的处理动作，不循环弹出授权或反复切全屏。
- 为 Mac 主窗口、鸿蒙首页、设置及全屏状态留出实机界面验证；同时核对录屏权限和反向输入权限的降级路径。

## 本轮不做

无线连接、多设备管理、虚拟显示器创建机制重做、可拖动屏幕排列、运行中调整画质、额外输入类型或音频。现有上屏结果不构成帧率目标或通用兼容性承诺。

## 待设计评审

以下是第一版信息布局，用于评审页面分工和阅读顺序，未定配色、尺寸或组件样式。

```text
Mac 主窗口
┌──────────┬──────────────────────────────────┐
│ 扩展显示 │ 正在等待平板                      │
│ 设置     │ 打开平板上的 DeskMate，然后接线  │
│          │                                  │
│          │ Mac ─────── USB ─────── 平板      │
│          │ 显示来源：当前所选扩展显示器      │
│          │ 画面发送、反向输入、查看诊断      │
└──────────┴──────────────────────────────────┘

鸿蒙平板
┌─────────────────────────────────────────────┐
│ DeskMate                             设置   │
│                                             │
│               等待 USB 连接                 │
│        打开 Mac 上的 DeskMate，再接线        │
│             在系统提示中允许连接            │
│                                             │
│   会话有效且用户主动返回后：返回画面          │
└─────────────────────────────────────────────┘
```

Mac 借鉴 Oink 将连接对象和主要工作区分开的做法，用 Mac 与平板的连接示意表达当前进度，不暗示支持排列或设备发现。鸿蒙沿用同一状态顺序，但以平板原生导航呈现。设计稿确认后再改应用代码。
